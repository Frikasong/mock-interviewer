# 面试准备三步法 · 调研、故事银行、模拟

面试转化率取决于**匹配度**，匹配度有两半：认识目标雇主（why them）和认识你自己（why me）。AI 只有在读得到这两份真实资料时才能言之有物；读不到，它只会产出对任何候选人、任何雇主都成立的万能话术——而这正是丢掉面试的原因。

所以这个 skill 先产出资料，再对着资料练。三步，顺序不能乱：

| 步骤 | 解决什么 | 产出 |
|---|---|---|
| 一、调研岗位 | 他们是谁、到底在考什么 | `company-dossier.md`、`why-them.md`、`question-bank.md` |
| 二、认识自己 | 我是谁、我的证据在哪 | `stories/S01…Sn.md`、`selling-points.md`、`self-intro.md`、`weaknesses.md` |
| 三、模拟面试 | 压力下我会丢掉什么 | `debrief-<日期>.md`，以及对上面所有文件的更新 |

如果用户一上来就说「直接帮我模拟面试」，而手上没有前两步的产出，先补一个最小可用版本——从 JD 倒推 5 道题、3 张故事卡、一版 30 秒自我介绍。对着空故事库做 mock 学不到东西，因为没有任何东西可以拿来对照表现。这一点一句话说清楚就开始做，不要说教。

## 工作文件

建一个以雇主命名的文件夹，全部落盘。这样下一个岗位可以复用，任何 AI 工具之后也能读回来。

```
<雇主>-<岗位>/
├── 01_why_them/   company-dossier.md, why-them.md
├── 02_why_me/     stories/, selling-points.md, self-intro.md, weaknesses.md
├── 03_questions/  question-bank.md, gap-list.md
└── 04_mocks/      debrief-<日期>.md（每场一份）
```

`assets/` 里有每个文件的空白模板，复制填写即可，不要另创格式——题库格式尤其重要，Mock Interviewer 直接解析它。

## 语言规则

笔记和讨论用用户习惯的语言都可以，但**所有会在面试中说出口的素材——STAR 故事、自我介绍、Why Them、答题开场句——必须用面试实际进行的语言写**。用母语想好再现场翻译，是答案发虚、语速掉、结论丢失最常见的原因。

面试语言不明确就问一句。跨语言场景（中文母语者面英文岗位）：故事卡正文用英文写，只在卡片底部留一行中文的「记忆锚」。

## 第一步 · 调研岗位

读 `references/01-employer-research.md`。四项产出：

1. **逐行拆 JD**——每条职责后面都藏着一到两道题。JD 不是招聘广告，是题纲。
2. **公司档案**——业务或法定职能、组织结构、最近 12 个月的关键动态。走搜索，每条标日期和来源；不确定的标 `[未证实]`，不要抹平。
3. **Why Them 三层论证**——我的轨迹为什么指向这里 → 我对它业务/方向的具体判断 → 我想参与它什么工作。然后套测试：*这段话如果原封不动能投给它最直接的竞争对手，就是没准备好。* 拿给用户之前自己先跑一遍这个测试。
4. **题库**——JD 倒推题 + 公开面经 + 岗位类型通用题，分成动机 / 行为 / 情景 / 公司专属四类。格式必须严格（`###` 一题一标题），Mock Interviewer 要解析。

## 第二步 · 认识自己

读 `references/02-story-bank.md`。

先对照 JD **逐行**逼问简历——每一行都问，不要只挑亮眼的。理由很实际：无法预测面试官会对哪段经历感兴趣，全覆盖是临场流畅度和信心的唯一来源。把问题清单交给用户，让他自己填。

**绝不替用户编造经历、数字或成果。** 素材必须来自他本人。他答得含糊时要追问：你个人做了什么（区别于团队）、有没有数字、谁反对过、后来怎么样了。含糊通常是谦虚或遗忘，不是真的没有——把难事做成了的人，往往会觉得那件事不难。

然后把原始素材拆成 10-15 张编号 STAR 卡（S01、S02……），一卡一文件，每张标注能回答哪些题型。比例是有讲究的：Situation 一两句带过，Action 占一半以上且主语必须是「我」而不是「我们团队」，Result 有数字就上数字。

最后产出卖点矩阵（雇主最看重的 3 个特质 × 对应证据故事）、30 秒和 90 秒两版自我介绍、以及弱项三段式——坦诚 → 已经在做的补救 → 落回岗位。

**进入第三步前先对账。** 给题库里每道题填上最优故事、次优故事和一句开场句；标不出好故事的进 `gap-list.md`。缺口清单决定剩下的时间花在哪——而不是把已经会答的题再练十遍。

## 第三步 · 模拟面试

读 `references/03-mock-and-debrief.md`。两种练法：

- **Mock Interviewer**（github.com/Frikasong/mock-interviewer）——一个用 Chrome 打开的 HTML 文件，有录像、实时转录和逐题计时。用户导入 `question-bank.md`（粘贴，或点按钮选文件），把 `selling-points.md`、`self-intro.md` 和这场要用的故事卡粘进「你准备了什么」，然后开始答。结束时下载一份 `debrief-….md`，文件顶部写好了教练 prompt。工具完全在浏览器里运行，写不进用户的文件夹——提醒他把这份文件存进 `04_mocks/`，再拿回来给你。
- **在对话里练**——你扮演面试官：一次一题、报出时长预算、等他答完、追问一个真实面试官会追问的问题，然后给反馈，再问下一题。不要一口气抛完所有题再统一点评——那是出卷子，不是面试。

**回填才是这一步的意义。** 复盘拿回来后，按文件顶部的四点批改（前 15 秒有没有结论、STAR 完整度、用时对预算、准备的 vs 实际说的），然后**改文件**：改 `question-bank.md` 里的开场句和 `watch:`、修订或新增故事卡、更新 `gap-list.md`、把答不上来的追问作为新题加进题库。留在聊天里的反馈下一场就没了；写进题库的反馈会复利。练过三场，这份题库会比任何公开面经都更贴合用户自己的弱点。

## 边界

- 不编造用户的经历、数据或成果。提问、结构化、润色，这就是全部工作。
- 不承诺结果。准备改变的是概率，不是结论。
- 涉及具体雇主的事实（财务、监管动态、组织变动）一律搜索并标注来源，绝不凭记忆写。
